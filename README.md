# Stardew Companion DB — ไฟล์ส่งต่อให้ Claude Code

ฐานข้อมูลส่วนตัวสำหรับแอป "My Farm" (PWA ส่วนตัว Stardew Valley 1.6 + SVE) สถานะตอนนี้: **รอบ 0 (pilot)** — วางโครงและพิสูจน์วิธีดึงแล้ว มีข้อมูลจริงแค่ Pumpkin 1 รายการ **ยังไม่ได้ดึงข้อมูลจำนวนมาก**

## โครงสร้าง
- `PLAN.md` — แผนเต็ม: แหล่งข้อมูล บทบาทของแต่ละเว็บ รอบการดึง วิธีตรวจ ข้อควรระวัง
- `SCHEMA.md` + `schema.sql` — โครงตารางและความหมายของฟิลด์
- `UPDATE.md` — วิธีอัปเดตข้อมูลโดยไม่ทับของที่แก้เอง
- `data/*.json` — **แหล่งความจริง** (หนึ่งไฟล์ต่อหนึ่งตาราง) แก้ที่นี่เท่านั้น
- `stardew.sqlite` — สร้างใหม่ได้เสมอจาก JSON ด้วย `python3 scripts/build_db.py` (อย่าแก้ตรง ๆ)
- `images/` — รูปไอเท็ม ตั้งชื่อตาม `image.id` (ตอนนี้ว่าง เพราะยังไม่ได้ดาวน์โหลด)
- `cache/` — wikitext ดิบที่ดึงมา (ไม่ต้องเก็บใน git ถ้าใหญ่)
- `scripts/` — `build_db.py`, `validate.py` (ทดสอบแล้ว) และ `fetch_wiki.py`, `parse_infobox.py` (ร่าง ยังไม่ได้รันจริง)

## กติกาสำหรับ Claude Code
1. ทุกแถวที่เป็นข้อเท็จจริงต้องมี `entity_source` (หน้าที่มา, เวลา revision, วันที่เข้าถึง) ถ้าไม่มี `validate.py` จะเตือน
2. ตัวเลขที่ยังไม่ได้ตรวจข้ามแหล่ง ตั้ง `verified = false` และ `confidence` ตามจริง อย่าเดา
3. ชื่อไทย: ถ้ายังไม่มี ปล่อย `name_th = NULL` และ `name_th_status = 'none'` ห้ามคิดคำแปลเอง ผู้ใช้เป็นคนแปลหรืออนุมัติ แล้วบันทึกผ่าน `user_override`
4. ข้อมูลจาก SVE ใส่ `content_pack = 'sve'` เสมอ ห้ามปนกับ vanilla
5. ก่อนเปลี่ยนโครงตาราง ให้ขึ้นเลข `schema_version` ใน `data/meta.json` และเขียนใน `changelog`
6. ไฟล์เกมจริงอยู่ในคอมอีกเครื่อง (ยังไม่ได้ดึง) เมื่อได้มาให้ใช้เป็น ground truth ตามรอบที่ 4 ใน `PLAN.md`

## เริ่มใช้งาน
```
python3 scripts/build_db.py && python3 scripts/validate.py
```
